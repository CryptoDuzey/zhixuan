## 2. 假设与实验设计

假设：维持每款事实65/限制25/场景10的预算、型号绑定及来源不变，先按本轮问句与条目/章节的字面匹配排序，再用原检索分数排序，可让靠后的相关资料进入回答。

只改上下文组装层：`app/lib/consult-context.ts` 与 `app/lib/consult.ts` 的条目选择。不改生成提示词、工具或证据保护。先将原选择逻辑提取，登记两个固定测试后运行红基线：后部接口条目应保留；空问句保持稳定顺序及原输入不变。之后实施排序变更，用完全相同的两轮选购问句实测。

成功标准：固定上下文预算仍为65，两个目标接口条目均保留；空查询对照不退化；真实原问题不再声称D14无接口资料，并准确区别两款接口。测试文件 `app/tests/consult-context.test.ts`，基线 `context-baseline.log`，之后 `tests-after.log`。

- 基线：固定后部接口测试失败，两个目标条目均在截取窗口外；真实回答“D14接口资料我这边没有”。

- 实际同样两轮输入：`03-consult-after`、`04-ports-after`。追问准确回答D14左USB-C/USB-A、右USB-A2.0、HDMI及音频接口，与Pro S两个USB-C作区分，不再假称D14无资料。本轮真实问题前后各一次，不冒充统计上稳定成功率。
- 定性限制：首轮比较仍有“兼容风险相对小”，且没有完整平衡展开Pro S；修复只证明相关事实进入上下文及该接口问答改善，未证明所有选购回答忠实。

“读取成功”不等于“需要的资料进入回答”；应另量测每个型号的关键字段覆盖。检索文档级分数不足以决定文档内条目，今后上下文预算回归应包含尾部字段与限制条件。
