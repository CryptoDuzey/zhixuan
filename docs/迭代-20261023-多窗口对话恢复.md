# 迭代报告：多窗口对话恢复

## 1. 靶点与诊断证据

前一轮完成真实短稿实验、撤回无效候选，属于有证据进展；本轮遵守停止继续扩写该类提示词的决定，处理独立的界面状态缺陷。

实际打开两个选购窗口：A询问Pro S柔光版24GB/512GB历史价格，B新建咨询并询问无线鼠标3价格。A刷新前仍是电脑对话，刷新后变成B的鼠标对话。基线保存在 `output/iterations/window-recovery-20261023/baseline.json`。没有发现记录被删除或请求串写，已证实的是刷新恢复对象错误。

原因：两端只从共享的“最近对话编号”恢复，各窗口没有独立地址标识。最近使用B后，A刷新也读到B。两端历史文件及恢复接口本身仍能读出原记录。

## 2. 假设与实验设计

只改界面会话定位层，不改生成提示词、检索、模型、服务器保存结构或运行协议。每个页面地址用一个有效chat编号固定当前对话；显式地址优先，普通入口无编号时仍兼容旧最近记录。新建与历史切换同步更新地址；无效或重复显式编号不回退打开另一条最近记录；创作交接仍优先建立独立对话。

固定验收：重复原选购A/B切换刷新两轮，再在创作端执行相同两窗口流程两轮；每次都检查恢复完成后的正文是否属于原窗口。对照：空对话刷新、无效编号、保留其他查询与页面锚点、浏览器存储不可用时的地址保存。成功要求原失败消失，两端8次恢复全部正确，无新增发送或重复生成。

基线在生产改动前实际观察并保存；没有建立可执行的旧实现函数评测，不能将新增4项帮助函数检查称为“基线4项失败”。本报告的实验设计文字在改动后整理，不冒充事前注册时间。后续迭代应先落盘判据，再实施改动。

## 3. 结果与失败变化

- 原选购场景：基线A错误打开B；修复后两轮×两个窗口，共4次恢复均回到各自记录。
- 创作端对照：两轮×两个窗口，共4次恢复均正确；价格聊天没有展开稿件画布。
- 空对话刷新仍可开始输入；无效地址没有显示旧鼠标或电脑记录。帮助函数检查验证地址优先、重复/无效编号、保留查询和锚点、保存失败返回值。
- 初次后测过早读取了“正在恢复”页面，观察值为false。该记录单独保存在 after-pending-observation.json；随后以咨询记录可见作为恢复完成信号，原样重复两轮，不把过早观察算修复失败或删去它。
- 最终完整检查543项：520通过、0失败、1跳过、22TODO；构建通过并已在3100加载。对应tests.log和build.log保留在本轮目录。此前短稿失败、事实审查缺陷不因这些检查通过而关闭。

恢复后的完整页面观察在 after.json、creation-after.json、empty-invalid.json，截图为 consult-a-after.png。旧版本已经打开且尚未固定地址的窗口，更新后首次加载仍只能沿用原先的最近记录；可从历史选择原对话，此后地址固定，不会声称旧版丢失的窗口关联已自动找回。

## 4. 固化决定

保留改动：新增 `app/app/components/conversation-location.ts`，Studio与consult均使用；新增 `app/tests/conversation-location.test.ts`。长期规则写入app/AGENTS.md。历史记录不迁移、不覆盖，保留旧入口的最近记录兼容。

## 5. 元反思

“记录持久保存”不等于“每个窗口恢复到自己的记录”；历史接口正常和单窗口刷新正常都没有覆盖此缺陷。回归应包含两个独立窗口、不同对话、交替刷新和历史切换。

旁路窗口确认分隔条反算存在数值偏差，并给出420组几何对照；尚未修改拖动实现。本轮尝试900×800覆盖，但实际DOM仍报告1280×720，因此不能宣称900宽度或窄屏验收完成。临时尺寸设置已撤销，比例复位默认40。数值诊断见 `output/iterations/workspace-split-20261023/report.md`；下一独立靶点可按真实布局继续验证拖动，不能把计算检查当实际拖动成功。
