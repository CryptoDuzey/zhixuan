# 知选产品需求

更新：2026-10-18。以当前代码与验收记录为准。

## 产品定位

同一知识依据支撑两个角色。顾客端从实际任务出发比较产品；营销端把明确的人群、场景和产品转成平台图文。采用对话推进、结果按需展开的轻量界面。

## 用户与场景

| 用户 | 日常任务 | 输出 |
| --- | --- | --- |
| 内容运营与导购 | 为学生、差旅等人群解释购买理由 | 公众号、小红书、朋友圈图文与依据 |
| 准备购买的顾客 | 明确任务、预算、软件与取舍 | 方案、候选产品、限制与核对清单 |

从“大学生”进一步明确到课程软件、携带频率和外设；从“商务”进一步明确到会议连接、企业软件、旅途中供电。未知条件不能写成已知事实。

## 已实现的功能

1. 营销端支持五款产品，未选产品不默认 Pro S，同名不同系统先澄清。
2. 基于指定资料的本地 API 读取原文、限制、场景卡、价格卡与对应图片。
3. 公众号、小红书、朋友圈分别遵守长度与图片数量规则。
4. 写作后独立模型核验，并组合引用、图片型号、价格条件及宣传表述检查。
5. 对话改稿与画布编辑触发当前版本重新核验，阻断问题未解决禁止导出。
6. 顾客端了解任务、预算和软件，再比较最多三个有依据的产品，可展开来源。
7. 选购结果可带产品与场景进入营销端，用户确认后发起创作。
8. 本机模型设置支持查询、测试、保存；密钥仅保存在服务端。

## 推荐与表达原则

像朋友提醒：先给解决办法，再说明为什么某项产品能力有帮助，同时说明取舍。没有必要购买时可以不推荐。不给虚构体验，不夸大兼容，不编造促销和紧迫感。价格仅明确询价后展示可核实的历史配置快照。

## 产品与证据

五产品：MateBook Pro S、MateBook 14 鸿蒙、MateBook 14 酷睿 Ultra、D 14 2024、D 16 2024。每款独立读取资料和图片，咨询跨产品比较时给依据编号加产品范围，避免相同编号互相串用。

核验是辅助检查，不等于所有事实已获得外部认证。资料来源一律保留“本地已下载知识库”。

## 暂不交付

实时热点 MCP、实时活动聚合、自动发平台、电商支付、账号权限和长期画像。当前为同一应用的两个页面入口，不需要部署两个网络端口。

## 验收重点

你好不触发默认产品；MateBook 14追问系统；切换产品不复用旧稿依据；D16图不够时说明；失败不显示完成；不同平台图片数量正确；改稿后重新检查；顾客推荐有对应产品依据；选购到创作参数正确；密钥不出现在页面、导出和仓库。
