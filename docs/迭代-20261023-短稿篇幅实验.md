# 迭代报告：短稿篇幅补救

## 1. 靶点与诊断证据

上一轮是实际修复与测试进展，本轮继续处理仍失败的创作任务。实际会话 `s-b9fcb221-8ec5-4848-80b7-0eeb680f4109` 要求朋友圈正文60至100字，没有生成可交付稿件。

固定复现沿用该会话前两轮真实聊天，再分别要求正文60至100、90至150、150至250字，每题重复两次。真实3100接口、真实模型、本地知识库和完整SSE均参与，没有模拟首稿或审核。复现脚本 `app/tests/short-writing.live.mjs` 保存候选正文流，补上原先无法看到被拒候选的诊断缺口；不修改产品输出协议。

基线短稿两次均失败：首稿111、143字，补救后109、134字。正常与扩写四次都交付了范围内稿件，但不因此认定事实质量全部合格。

## 2. 假设与实验设计

实验1仅改写作提示：显式正文预算替代平台默认篇幅，短稿选一项相关依据，必要条件不能截断。模型、检索、图片集合、JSON字段、补救次数和硬性字数门槛均不变。

实验2在第一版已失败并恢复后，仍只改提示层：预算内先选能完整表达条件的事实，所有篇幅均排除从尺寸、重量、比例直接推导使用效果。没有改评测题或放宽成功标准。

成功要求：两次短稿都在范围内，四次对照保持交付；逐稿检查必要事实条件、无依据效果及图片，不以字数通过代替可发布。注册记录与同批输入摘要保存在 `output/iterations/short-writing-20261023`。两次实验各自有2次重复，没有把实验1和实验2当作同一方案的稳定性重复。

## 3. 结果及失败样本变化

| 固定样本 | 基线正文 | 实验1正文 | 实验2正文 |
| --- | --- | --- | --- |
| short-1 | 失败，补救109字 | 93字 | 91字 |
| short-2 | 失败，补救134字 | 89字 | 失败，补救108字 |
| normal-1 | 130字 | 143字 | 143字 |
| normal-2 | 136字 | 144字 | 失败，补救159字 |
| expanded-1 | 205字 | 244字 | 241字 |
| expanded-2 | 176字 | 246字 | 230字 |

短稿交付：0/2→2/2→1/2；正常和较长对照：4/4→4/4→3/4。实验1字数有收益，但 normal-1 出现“装包更省空间”，expanded-2 出现“负担会小一些”“纵向能多显示几行”等未建立比较或效果依据的表述，不能保留。实验2又出现正常对照退化；short-2补救原样返回108字，未满足门槛。

全部失败及完整会话保留在 baseline、after-r1、after-r2 子目录。独立窗口另作逐稿事实及图片复核，结论见同目录 independent-review.md；这些复核不能替代基线或将未交付任务计为成功。

## 4. 回滚与停止决定

两版提示改动均已撤回。`agent.ts`、`prompts.ts` 恢复为实验前保存的原字节；候选源文件、候选测试和决策记录单独保留。原来的价格、历史分页、聊天与工作台修复不受本轮回滚影响。

回滚字节摘要核对见 rollback-proof.json：两文件前后一致。恢复后完整检查539项，其中516通过、0失败、1跳过、22TODO；候选专用3项测试已归档为文本，不当成保留功能的检查。恢复构建通过，3100重新运行恢复版，浏览器刷新可读到原对话和失败状态、没有空白画布。未把错误目录下的一次未执行成功的测试命令计入验收。

独立审阅确认18条全部结束；已交付稿均有一张正确库图。“只有两个USB-C”在完整证据中有明确原句，本批不能将它视作错误；审查发现的重量条件缺失及无依据效果均保留，模型报告pass不覆盖人工发现。

按连续两次无整体正向收益的停止规则：**当前已收敛，建议人工介入**。此结论仅表示停止这条提示词改写路线，并不表示短稿能力已经解决，也不表示整个产品已完成。未经新的明确授权或新的根因证据，不继续同类提示扩写。

## 5. 元反思

1. 只统计最终字数会奖励删除条件或添加无依据效果的稿件；必须逐项保存被拒候选、事实依据和图片方案。本轮脚本已保存实际流式候选，后续可直接复用失败样本。
2. 补救模型并不能可靠执行它收到的字数范围；只增加提醒并未解决问题。若继续此靶点，应由人工评估正文规划、条件预算或输出契约层的方案，单独登记实验，不能暗中增加重试或截断正文。
3. 图片旁路实看5张：文件与摘要5/5一致，但不能仅凭外观确认完整型号。D16SE来源有型号混用疑点，X Pro画面细节不足，仍暂缓；没有将其自动标成可用产品图。报告见 `output/iterations/kb-image-visual-20261023/review.md`。
4. 全量索引、绿色构建和大量函数检查均不能证明用户任务可靠。仍需修复当前生成失败、事实审核漏检，并补足至少三份合格作品和赛事要求的录屏、说明书及公开访问验证。
