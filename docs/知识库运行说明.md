## 读取与搜索接口

所有请求只接受 GET，不接受请求正文，未知或重复参数会被拒绝。

| 接口 | 行为与边界 |
| --- | --- |
| `/health` | 当前读取进程、目录快照、限制与请求计数；不占用普通读取或混合查询名额 |
| `/documents` | 默认返回完整目录；超出传输上限会明确413，不静默截取 |
| `/documents?limit=200&offset=0` | 目录显式分页；返回 `total`、`hasMore`、`nextOffset` |
| `/document/meta?id=资料编号` | 返回单份资料的元数据；先回读来源、核验路径和内容摘要，不依赖整目录大小 |
| `/document?id=资料编号` | 按已登记编号读取原字节，重新核验路径和内容摘要；无任意路径读取功能 |
| `/search?q=关键词` | 搜索全库文字与路径，多个空白分隔词须全部匹配；默认返回全部字面匹配项 |
| `/search?q=关键词&limit=200&offset=0` | 字面匹配分页，`total` 是分页前总数 |
| `/search?mode=online&q=关键词` | 明确返回 `onlineError.code=ONLINE_UNSUPPORTED` 和空结果，不会调用 ima |
| `/rag/health` | 实际探测混合查询端健康、核对全库数量和指纹 |
| `/rag/search?q=问题&strategy=hybrid&top_k=50` | 对全库索引排序并返回至多50条结果；每条回读原文核验 |
| `/rag/answer?q=问题&top_k=5` | 混合检索后给出有原文引用的短答、追问或证据不足状态；不接受 `strategy` 参数 |

目录和字面搜索的 `limit` 为1至200，`offset` 为非负安全整数。字面查询最多200个 Unicode 字符；混合问题最多1000个；混合 `top_k` 为1至50，支持 `exact`、`lexical`、`vector`、`hybrid`，应用应使用 `hybrid`。适配器与混合引擎的URL限制均为16384字节；1000个Unicode字符按最坏情况编码占12000字节，连同正常接口参数可完整传输。1000字符上限仍独立校验，1001字符明确拒绝，不静默截取。适配器的请求头上限为24576字节。

目录收全应从 `offset=0` 开始，持续读取 `nextOffset`，直到 `hasMore=false`，同时核对各页 `indexFingerprint` 一致。不能只拿第一页就标为全库资料。

查看单份原文时，应用先请求 `/document/meta?id=...`，再请求 `/document?id=...`，对原字节计算SHA-256并与元数据比对，不再先读取全目录。元数据成功响应如下；`source`、`indexedAt`、`indexMode`、`indexFingerprint`、`indexStale` 说明读取快照，`item` 仅包含该份资料：

```json
{
  "source": "本地已下载知识库",
  "indexedAt": "索引建立时间",
  "indexMode": "snapshot",
  "indexFingerprint": "全库内容指纹",
  "indexStale": false,
  "requestId": "同响应头x-request-id",
  "item": {
    "id": "24位小写十六进制编号",
    "title": "资料标题",
    "path": "知识库内相对路径",
    "bytes": 123,
    "sha256": "原文件字节的SHA-256摘要",
    "source": "本地已下载知识库"
  }
}
```

元数据接口只接受唯一的 `id` 参数：缺失、重复或额外参数为400；未知或格式错误的编号为404；原文变化、删除或替换为外链时为409。即使整目录响应超过2MiB而返回413，单份元数据和符合各自大小限制的原文仍可读取。

混合检索返回 `retrievalScope=all-indexed-documents`、`scannedLocalFiles`、`indexFingerprint`、`items`/`results` 和：

```json
{
  "resultWindow": {
    "maximumTopK": 50,
    "returned": 50,
    "paginationSupported": false,
    "exhaustive": false
  },
  "semanticRecallGuaranteed": false,
  "answerCorrectnessGuaranteed": false
}
```

`scannedLocalFiles` 是索引覆盖量，`returned` 是本次返回量，`totalCandidates` 是参与排序的候选范围；这些数值均不是“全部真正相关资料”的数量。现有混合引擎没有分页，超过50份的语义相关结果无法通过不断修改前端页码取全。

文字片段的 `start`、`end` 按 Unicode 字符计数，`end` 不包含在片段内，`offsetEncoding=unicode-code-points`，`newlineMode=original`。适配器已转换 Python 短答和 exact 的换行位置；前端若定位原文应使用 `Array.from(text).slice(start, end).join('')`，不能直接按 JavaScript字符串位置切片。

## 短答格式与前端呈现

前端应按状态决定呈现内容：

| 状态 | 建议显示 |
| --- | --- |
| `answered` | 简短结论、同条事实的引用、适用型号/年份、限制条件和资料日期 |
| `clarify` | 需要确认的问题；不把检索第一条直接写成事实 |
| `insufficient_evidence` | 明确提示资料不足，并指出可补充的信息 |
| `unavailable` | 服务异常或超时提示与重试入口；不伪装成“没有相关资料” |

`answered` 的每条 `claim` 必须等于其引用的完整原文摘录；最后 `answer` 必须由这些事实及引用编号组合。引用真实但事实被改写或编造时，适配器拒绝返回成功。`source_fact`、`limitation`、`to_verify` 分别表示原文事实、限制和待核验信息。不能隐藏限制句或将排序分数展示为正确概率。

引用至少保留资料编号、相对路径、摘要、原文片段和可查看链接。适配器的链接为 `/document?id=...`；应用使用 `/api/knowledge/document?id=...`，经单份元数据接口获取摘要，再核对实际读取的原字节。多个版本或型号不能互借参数。没有明确日期的资料不应被标成实时信息。

这些核验可以拦截伪造引用和修改摘录，但不能证明原资料准确、过期信息仍适用，或摘录与问题的意思完全一致。需要针对错误型号、版本冲突、否定问题和资料冲突持续做人工标注评估。

混合探测另有1个名额。查询名额耗尽时不会占用这个探测名额，但8766自身可能已饱和；8767的独立进程健康也不能代替一次成功查询。

总处理期限覆盖上游探测、响应头、流式正文和异步原文回读；调用者断连会取消后续工作并释放名额。同步运算仍受单进程调度影响，15秒不是操作系统级硬实时保证。后端取消也不保证已开始的 Python 推理立刻终止。

上游健康信息限64KiB，普通 JSON 传输限2MiB，单份原文件与每次混合来源累计回读各限64MiB。超限明确拒绝，不能先截断再返回“成功”。`items` 与 `results` 同时输出会计入最终响应大小，大片段可能在上游大小合规后仍触及最终上限。

所有由适配器处理的失败使用 HTTP状态与一致正文：

```json
{
  "schemaVersion": 2,
  "status": "unavailable",
  "reasonCode": "UPSTREAM_TIMEOUT",
  "error": {
    "code": "UPSTREAM_TIMEOUT",
    "kind": "local",
    "message": "读取或检索超时，请稍后重试。"
  },
  "requestId": "同响应头x-request-id",
  "retryable": true,
  "answer": "",
  "claims": [],
  "citations": [],
  "items": [],
  "results": [],
  "abstained": true,
  "evidenceSufficient": false

```

兼容注意：适配器的 `error` 现在统一为对象，不能再按旧版混合服务的错误字符串读取。`reasonCode` 可用于判断；不直接展示任意上游错误内容。HTTP解析器在进入接口处理前拒绝的坏请求可能由 Node 直接回复，不保证此正文结构。

| HTTP状态 | 主要代码 | 处理 |
| --- | --- | --- |
| 400 / 414 | `INVALID_REQUEST` / `REQUEST_TOO_LARGE` | 修正参数或缩短问题 |
| 404 | `DOCUMENT_NOT_FOUND` / `ROUTE_NOT_FOUND` / `NOT_FOUND` | 重新获取目录或检查接口 |
| 409 | `INDEX_STALE` / `RAG_INDEX_MISMATCH` | 核对资料、重建索引并刷新读取快照 |
| 413 | `DOCUMENT_TOO_LARGE` / `EVIDENCE_TOO_LARGE` / `RESPONSE_TOO_LARGE` | 分页或缩小问题；不可忽略缺失部分 |
| 502 | `UPSTREAM_INVALID_RESPONSE` / `UPSTREAM_RESPONSE_TOO_LARGE` / `UPSTREAM_REDIRECT` | 检查服务契约和配置，不将错误内容当答案 |
| 503 | `BUSY` / `UPSTREAM_BUSY` / `UPSTREAM_UNAVAILABLE` / `RAG_NOT_CONFIGURED` / `RAG_NOT_READY` | 检查配置、负载或服务状态 |
| 504 | `UPSTREAM_TIMEOUT` / `REQUEST_TIMEOUT` | 有限重试；避免叠加无上限请求 |

503/504带 `Retry-After: 1`。调用者断连只取消并计数，不向已经关闭的连接发送499正文。有效的请求编号为8至80个字母、数字、下划线或短横线，否则生成新编号。

`/health.rag.status` 为 `disabled`、`unverified`、`ready`、`mismatch` 或 `unavailable`。其中 `configured=true` 只表示设置了地址，`ready` 也只是上次观察结果，须结合 `checkedAt` 和 `scope=last-observation-only` 解读。指标为当前进程内计数，重启会清零。

适配器使用启动快照。新增文件需重启重新建立目录，并重建引擎索引。普通目录、元数据和原文读取不等于实时监控所有未返回文件；混合查询则每次在引擎完整读取全部文件核对指纹，再由适配器核对同次绑定及返回来源。这是请求时的完整校验，不是持续文件监控。

搜索和短答成功响应包含以下绑定；`fingerprint` 必须与 `indexFingerprint`、适配器启动快照一致，文件数须相同。缺少绑定的旧引擎响应明确失败，不降级为未核验查询。
