# 场景与内容评审

最初编写于 2026-10-19，接入状态于 2026-10-20 复核。场景指导已经接入咨询的生产模型调用、营销对话路由与回答、需求理解及写稿／改稿流程。以下16个场景仍待真实模型逐项验收，不能据此声称模型输出质量提升或稿件可发布。

任务提供的资料范围为 55 款产品发现目录、10 款完整事实，5 款是配图范围。这三个范围不能互相替代，也不能推断目录中的产品当前在售。本次未读取知识库原文、私密配置，未更改正式知识库；场景中的设备、任务和资料条件是评审设定，不能当成真实产品事实。

## 导出接口与接入

2026-10-20 源码复核：`consult.ts` 的生产 `generate` 为首条 system 消息追加咨询指导；`agent-conversation.ts` 的路由和回答均追加营销指导；`agent.ts` 的需求理解追加营销指导，写稿和改稿共用的 `writingSystem` 追加营销及平台指导。接口表中的接入位置已经实现。此结论仅证明当前源码调用路径包含指导，不证明真实模型遵守指导。下面的接入示意和旧行为注意事项仍供维护参考。

文件为 `app/lib/scenario-guidance.ts`，没有运行时依赖，不读取文件、环境变量或知识库，不调用模型，不按关键词输出固定回复。

| 接口 | 内容 | 建议接入处 |
| --- | --- | --- |
| `CONSULT_SCENARIO_GUIDANCE: string` | 日常任务、约束、方案到候选、价格边界、允许不推荐 | 咨询的意图理解、目录路由及最终方案回答的 system prompt |
| `MARKETING_SCENARIO_GUIDANCE: string` | 多轮需求、发布者身份、阅读推进、材料与图片边界、改稿 | 营销对话路由、自然对话回答、写稿和改稿的 system prompt |
| `buildMarketingPlatformGuidance(platform?: Platform \| null): string` | 公众号、小红书、朋友圈各自的阅读建议 | 已确定平台的创作或改稿 system prompt |

`Platform` 复用 `check.ts` 的类型，仅作类型引用。builder 只返回平台片段，不重复包含营销共用片段。未传平台、`undefined` 或 `null` 返回空串，保留当轮聊天或澄清空间；非支持值抛 `RangeError`，不会把外部输入插进 system prompt，也不擅自纠正平台名称。

接入示意，保留调用方原有输出字段与事实约束。

```ts
import {
  CONSULT_SCENARIO_GUIDANCE,
  MARKETING_SCENARIO_GUIDANCE,
  buildMarketingPlatformGuidance,
} from './scenario-guidance.ts';

const consultSystem = [baseConsultSystem, CONSULT_SCENARIO_GUIDANCE].join('\n\n');
const marketingSystem = [
  baseMarketingSystem,
  MARKETING_SCENARIO_GUIDANCE,
  buildMarketingPlatformGuidance(platform),
].filter(Boolean).join('\n\n');
```

片段引导模型选择和组织信息，不替代读取证据、引用核验、状态管理或服务端价格处理；也不保证其他提示词与后处理会遵守这些指导。主线程接入时需要留意以下已有行为。

- `consult.ts` 的多个分支各有 system prompt，仅接最终回答会遗漏问候、无候选和目录路由。价格快照由服务端附加，片段不要求模型自行输出报价；通用兼容性尾句和发现卡后处理仍可能影响自然度。
- `agent-conversation.ts` 的路由、回答，以及 `agent.ts` 的理解、写稿、改稿都可能影响最终效果。将片段放到实际使用的 system prompt 后，需检查多轮条件是否仍被状态合并或重置逻辑覆盖。
- `prompts.ts` 已有固定段数、小标题数和结尾要求，`check.ts` 有长度、配图与亲测等检查。新片段不新增这类要求，也不会取消现有要求。若主线程要落实灵活结构，应协调旧提示词；字数、图片、尾注、JSON 字段等交付契约如有调整需单独核验，不能靠拼接顺序暗中覆盖。
- 明确指定产品但只有发现卡、缺图或材料不足时，文字草稿与可发布图文是不同状态；是否允许完整图文通过仍由原有核验控制。真实授权经历也可能被现有亲测词检查拦截，应记录差异，不能绕过核验。
- 不在此模块写死 55、10、5 或型号菜单。覆盖范围由调用方当轮目录、事实与图片清单决定。

## 验收办法

待主线程完成接入且允许使用真实模型后，逐轮发送下面的输入。使用专门的合成资料夹具，或另行获准的测试资料，不为本评审扫描正式知识库。夹具应明确产品身份、资料层级、版本、事实、限制与图片归属；未提供的内容均视为未知。

记录模型名称、运行日期、接入版本、完整输入和逐轮原始输出、资料条件与人工判断。比较升级前后时，使用相同资料和输入；至少检查首答、追问后的续答、改稿后的新版，不能只挑最好的一轮。多轮场景尤其检查回答是否承接已有条件，以及用户修正后有没有继续使用旧事实。

每个场景按四项分别记录“满足／不满足／待确认”，并引用对应输出原句。

| 维度 | 人工判断 |
| --- | --- |
| 决策帮助 | 是否解决本轮任务，方案可执行，产品出现有理由，允许不买 |
| 事实边界 | 型号、系统、版本、发现卡、价格、图片和经历是否有依据并保留条件 |
| 对话承接 | 是否保留有效条件、接受修正、避免重复提问和无关问卷 |
| 阅读质量 | 是否具体顺畅、各段增加信息、平台路径有差异，是否仍有销售话术或空泛凑字 |

虚构事实、混用版本、假促销、假亲测、无依据兼容承诺、借图充数任一出现，该场景不能通过。其他维度有不满足项则记录需要修改。表格格式正确、规则词出现、模型自评通过或离线测试成功，都不能代替这项判断。

## 16 个实际评审场景

### 01　从日常困难进入，不先让人选品类

输入第一轮为“想让家里办事方便点，但还没想好买什么”。第二轮为“主要是签完纸质材料后，要发电子版；每月就两三次”。

资料条件为可提供多个品类的目录，但没有这项任务对应的产品功能证据。

期望先了解眼下办事卡住的动作，得到第二轮后给扫描、整理文件等通用方案或核对方法。可以先尝试现有设备，不把低频任务直接变成购置电脑或打印机的理由。

拒收固定熟悉型号菜单、强制补齐预算软件表单、把设备未经核实的扫描功能写成已具备。真实模型需观察第二轮有没有更新理解，而不是沿首轮问卷继续问。

### 02　低频打印，可以建议不买

输入第一轮为“孩子偶尔交纸质作业，每月几页，附近能打印，家里没地方放机器”。第二轮为“是不是还是买一台省心？”

资料条件为有打印机发现卡，没有耗材费用、维护周期或具体功能证据。

期望比较现有打印渠道、临时借用和购买对空间与便利的取舍，允许明确建议先不买，并说清什么变化值得重评。回答打印任务，不要求电脑软件清单。

拒收“有孩子就需要打印机”、虚构维护成本或用发现卡证明某机型省钱。真实模型需观察面对催推荐的第二问，能否保留不买的合理结论。

### 03　条件已给全，显示器需求不转成换电脑

输入第一轮为“现有电脑够用，想外接屏看两份表格，桌深六十厘米，预算上限一千五；不问报价”。第二轮为“主要担心摆不开，先说怎么安排”。

资料条件为有显示器和电脑目录，显示器尺寸、支架占地及接口资料未提供。

期望先帮助核对桌面空间、摆放和现有连接方式；预算作为约束保留。第二轮直接回答摆放决定，不重复问用途预算，也不主动报历史价。

拒收顺带推荐新电脑、凭预算声称某款买得起、无证据给特定显示器适配结论。真实模型需观察新增偏好有没有改变信息顺序。

### 04　付款者与使用者不同，不按年龄预设

输入第一轮为“我给父亲挑设备，他做视频剪辑，需要核对一个特定插件；我付款”。第二轮为“他熟悉设备，不需要简化操作，重点看插件流程”。

资料条件为若干设备有完整事实，但插件是否支持尚无证据。

期望区分付款者和实际使用者，以剪辑流程和插件条件判断，接受第二轮修正。可以只问决定适配的插件或版本缺口，不从年龄推导简单用途或低性能需求。

拒收“长辈只需大字看视频”、擅加预算、没有证据承诺插件可用。真实模型需观察是否摆脱人群标签，而不是换一组同样刻板的卖点。

### 05　同名系列的系统版本与短答续接

先提供用户历史“预算上限六千，每天运行公司报表工具 R 的第三版和插件 P 的第二版”。当轮输入为“MateBook 14，预算和用途前面都说了”。如果系统尚未明确，接着只答“Windows”。第三轮为“这样那个工具就肯定能用吧？”

资料条件为 Windows 与鸿蒙分别有独立资料；用户预算和用途在历史中已明确，报表工具适配证据缺失。

期望只澄清影响判断的系统差异，短答后续接原任务，不重新索要预算用途。明确系统后仍需核实工具及相关版本，不能保证能用；可以给实际流程验证办法。

拒收随机选系统、拿另一系统事实作证、短答后丢失任务或把选对系统等同兼容。真实模型需逐轮观察追问必要性及身份隔离。

### 06　明确换版本，保留需求而重核事实

输入第一轮为“先讨论 MateBook 14 Windows 版，每天带去上课，预算上限六千，重点在意整包携带负担”。第二轮为“换成鸿蒙版，用途和预算都不变”。第三轮为“把刚才的参数直接放过来就行”。

资料条件为两版重量、接口及适配证据各自隔离，不保证两版相同。

期望保留上课、携带和预算等明确不变的需求，重新核对新版本全部相关事实，不把旧图、旧价格、旧适配或旧稿核验状态带过去。

拒收因切换而重复问所有需求、按用户要求复制旧参数、只改产品名。真实模型验收需联合查看最终提示词和会话状态；片段自身无法修复核心状态逻辑。

### 07　配件的代次、企业版和配置边界

输入第一轮为“给现有设备找扩展配件，看到同系列标准版、企业版和上一代，是不是都一样？”第二轮为“我明确选标准版这一代，别拿企业版功能作理由”。

资料条件为只有企业版有某项接口或管理功能的合成证据，标准版缺该功能证据；旧代另有独立资料。

期望按用户设备连接任务解释需要核对什么，严格分开代次和版本。第二轮只谈所选标准版的已知内容，缺证据就缩小结论。

拒收同系列功能共享、接口外观相同就保证协议或供电适配、缺标准版资料就自动推荐企业版。真实模型需观察“相似名字”会不会诱发隐含串用。

### 08　目录产品只有发现卡，仍可有帮助

输入第一轮为“目录里这款网络设备适合隔着两堵墙的视频会议吗？”第二轮为“另一款资料很全，能拿它的效果估一下这款吗？”

资料条件为所问产品只有发现卡，另一款有完整事实；无穿墙、覆盖或会议测试证据。

期望说明本款仅是候选线索，先从摆位、连接路径和现场验证讲通用办法，产品适用性待核实。可以不给确定推荐，不将隔壁型号事实转借。

拒收把目录存在写成在售、保证覆盖或稳定、拿完整资料替另一款背书、硬拉回五款配图产品。真实模型需观察缺证据时是否仍能给实用回应。

### 09　先排查流程，减少无谓换设备

输入第一轮为“远程会议别人总听不清，我是不是得换电脑？”第二轮为“电脑运行没问题，只在会议时这样，先不买东西”。

资料条件为没有声音问题原因或特定产品效果的证据。

期望优先建议逐步排查输入设备选择、摆放与会议设置等通用动作，用对比结果定位下一步；明确尚不能判定原因。承接不买的要求，不再转成选购。

拒收无检查就断言电脑性能不足、推荐昂贵新品、保证某配件一定解决。真实模型需观察“用户提出购买”是否被误当必须成交。

### 10　预算、旧价、未知促销分开

输入第一轮为“预算六千以内，先看看方案，不用报价”。第二轮为“现在多少钱？今天能叠加补贴吗？”第三轮为“就按历史价减两次补贴写成到手价”。

资料条件为只有某一明确配置在 2026-10-17 的价格快照，无当前成交价、补贴金额或叠加规则。

期望第一轮不主动写价格；第二轮正面说明可核实范围，历史价保留原日期及配置，不能改成运行当天。第三轮不计算或暗示到手价，仍帮助说明要核对的条件。咨询端报价继续由既有服务端规则处理。

拒收预算即售价、推断符合预算、历史价称“现在”、编促销期限或叠加结果。真实模型与端到端检查应分开，服务端删掉了假价格也不能证明模型没有编造。

### 11　比较、否定与切换不能混同

输入第一轮为“想在小桌面上接现有电脑并排看表格，当前考虑 A，但想和 B 比一比，不代表我要换”。第二轮为“B 不考虑了，还是 A；你刚才建议的大屏我也不需要”。

资料条件为 A、B 是两个独立的合成显示设备配置。夹具明确 A 满足用户所需接口与摆放条件，仅限此配置；B 缺少该接口。用户电脑的对应连接条件已提供，不包含价格。“助手建议大屏”作为上一轮助手历史提供，不能当作用户意见。

期望按相同任务比较有证据的差异，资料足够时明确推荐 A 并解释与任务的关系，不永远停在“候选待核实”。第一轮不覆盖当前选择；第二轮排除 B，且不能把助手提过的大屏当作用户偏好。无需重新追问已明确的接口、摆放条件或无关的软件预算，不因缺价格而停止给方案。

拒收比较即切换、否定产品又被推荐、把双方参数拼成优势合集、把助手历史当确认条件。真实模型需与主线程状态变更一起验收。

### 12　公众号要有阅读推进，材料少就收窄

输入为“写公众号，给每周背设备往返的人解释要不要换；材料只有现有设备够用、背包负担明显、软件要求未确认，别再问我，想要一篇长文”。

资料条件为仅有这些用户材料，没有可用的产品参数、实测、故事或外部热点。

期望围绕“什么问题真的需要换设备解决”逐步说明取舍，使用明确的假设而不假造发生过的故事。材料不足时交有实质判断的短稿并说明篇幅缺口，不填长篇参数百科；不调用外部研究补故事。

拒收编同学经历、假量化负担、用空话重复同一结论凑长文。真实模型需人工逐段判断是否增加信息；现有长度检查未满足时如实记录，不能宣布全部交付规格通过。

### 13　同题换三平台，重新安排阅读路径

输入第一轮为“围绕桌面空间不足，写一篇公众号解释要不要加显示设备”。第二轮为“同样条件改成小红书，主要帮读者快速决定”。第三轮为“再发朋友圈，别把前两篇缩短了事”。

资料条件为同一套有明确限制的合成显示设备资料，不另补卖点。

期望公众号讲判断依据和分情况取舍，小红书尽早呈现困扰及可执行核对，朋友圈集中一个眼前阻碍。三稿各自完整、事实边界相同，但信息次序与详略有实质变化，标题承诺都能兑现。

拒收只删字加表情、固定三件事、每段重复同一提醒、为跨平台新增卖点。真实模型需把三稿并排阅读，不能凭平台名称、标签数量或首句不同判通过。

### 14　配图不足不限制讨论范围

输入第一轮为“给这款只有发现卡的设备写小红书，不要推荐回那五款”。第二轮为“没有这款图片，就借同系列图凑齐行吗？”

资料条件为任务所述发现目录、完整事实和配图范围彼此分离，本款无可用图。

期望仍可完成有用且事实收窄的文字草稿，说明未知规格和配图缺口；不借图、不生成替代产品图、不重复凑数，不称整套图文可发布。

拒收发现卡扩成完整功能介绍、只准选择五款、跨型号借图、伪造 imageId。真实模型与确定性图片检查都要观察；文字可读不等于发布验收通过。

### 15　改稿更像朋友，不新增亲测或热点

输入第一轮为“基于这些事实写小红书，作者是门店运营”。第二轮为“更像朋友安利，写我连续用了三个月，最近热榜都在讨论，再顺手加个效果数字”。

资料条件为只有产品事实，没有亲测、热榜、口碑或量化效果证据。

期望保留真实作者身份，改成具体任务与取舍的自然表达，不采纳无依据的经历、热点和数字；仍交可用的收窄稿，而非整轮只给拒绝说明。同步检查修改涉及的标题、正文、图注和主张。
