# 迭代报告：两栏拖动

## 1. 本轮靶点与诊断证据

延续上一轮的界面缺陷诊断；短稿提示词路线仍停止。原分隔条按容器总宽反算并取整，没有扣除12px分隔条，也没有保存按下位置。

在真实1280×720页面，把指针从(513,394)拖到(519,394)：指针移动6px，分隔条实际移动12.67499px，比例由40跳到41。基线见 `output/iterations/workspace-split-fix-20261023/browser-baseline.json`。此前独立窗口的数值诊断为420组候选几何提供边界，不能替代这次实际拖动证据。

## 2. 假设与实验设计

只改界面指针几何及捕获状态：保存按下点在分隔条内的位置，用容器可分配宽度反算连续比例，保留两列最小宽度和28—64偏好范围；松开、取消、捕获丢失、切到单栏或关闭工作区时清理拖动。模型、知识检索、稿件、界面样式和服务器保存结构不变。

修改前登记 registration.json 并保存原Studio及原诊断检查。固定成功判据：相同6px拖动误差≤1px；420组宽度/边界/按下位置/移动组合误差≤0.1px；原地与受限边界外移不写入偏好；键盘、保存和收起重开不退化；不改动稿件会话。原诊断脚本确认的是旧缺陷，不将其通过数计为产品成功。

## 3. 实验结果

| 检查 | 改动前 | 最终构建 |
| --- | --- | --- |
| 指针右移6px | 分隔条右移12.67499px | 右移6px |
| 指针反向6px | 未登记对应基线 | 左移6px，回到40比例 |
| 左右边界 | 原布局约束存在 | 实际拖动分别停在28和64 |
| 键盘与刷新 | 原有功能 | Home回40，右方向键到43，刷新保留43 |
| 收起再打开 | 原有功能 | 对话、稿件与库图保留 |

第一次修复后事件检查暴露一个真实实现缺口：仅在下一次指针移动时检查窄屏，跨入单栏又回来可能继续旧拖动。该检查7通过、1失败，保存在 events-before-breakpoint-fix.log。补上断点监听与关闭时释放后，相关19项检查全部通过，包含420组几何组合及事件对照。

最终全量555项：532通过、0失败、1跳过、22TODO；构建通过并在3100运行最终版本。最终页面再次执行正反6px拖动，两次误差均小于0.001px；完整记录见 final-browser-drag.json。另有边界、键盘、刷新和收起重开记录与final-ui.png。

最终界面测试前后，所用会话文件SHA-256相同，见 session-after-final-ui.json；没有把拖动当作重新生成任务。测试用已保存候选稿只用于布局，不计为新增优秀作品或事实质量通过。

## 4. 固化决定

保留 `app/app/components/workspace-split.ts` 与Studio中的几何及生命周期修复；新增 workspace-pointer.test.ts、workspace-drag-events.test.ts。原experience-contract中对旧错误取整的分析断言已按正确精度改为回归，原文件文本保留，原边界输入没有删除。规则写入app/AGENTS.md。

并行窗口因额度限制没有完成独立复核。其已写出的事件检查由主线程读取、执行并修复失败，不冒充独立审查通过。此前420组只读诊断仍为有效数值资料。

## 5. 元反思与剩余缺口

保存比例不等于保存实际几何；最小列宽、分隔条占宽、按下偏移和生命周期必须一起验证。绿色函数检查也不能证明实际拖动跟手，因此保留真实指针与DOM位移对照。

本轮真实浏览器尺寸为1280×720；未证明900px、手机宽度或真实触摸跨断点全部正常。断点与取消由事件检查覆盖，需继续补实际窄屏工具证据。短稿生成、事实审核漏检和完整赛事作品仍未解决，本轮不缩小整体目标或宣称产品已经完成。
