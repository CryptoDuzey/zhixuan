# 迭代报告：演示前测试与收尾

日期：2026-10-23。以下是两个先后进行、分别留有基线的最小实验；不是一次混改多个层面。所有失败原件保留，不以录像成功代替全产品验收。

## 实验一：普通建议被当作极限宣传

### 1. 靶点与诊断证据

实际样本 `final-xhs-student-1792739864915` 的“装进书包前最好自己掂一下”和“先别把它定成唯一答案”被拦截。该稿另外四项事实问题确实需要处理，不能因为普通建议误报而放行整稿。基线及登记见 `output/iterations/advice-check-20261023/`。

### 2. 假设与实验设计

假设：只识别明确自主检查建议、否定唯一答案的句式，可以减少误拦，同时保留真正宣传语拦截。仅改 `app/lib/check.ts` 的确定性检查，不改生成提示、检索和事实检查协议。固定两条建议、八条宣传/双重否定/混合句反例。成功条件：两条建议无此项误拦，八条反例仍拦截；真实事实风险仍不能导出。新增 `app/tests/advice-absolute.test.ts`。

### 3. 结果与失败样本变化

基线测试为红，首先在“最好自己掂一下”失败；原检查对“最好/唯一”均按关键词拦截。改后固定两条建议通过、八条反例仍拦截，相关19项检查通过。定性判断：自主检查动作不再被当成产品优越性，未放宽真实产品断言。

新实测 `s-76629867-368b-4978-9188-41e9d77ca414` V3 又出现“最好让对方拍一张接口照片”误拦。这不在登记的狭窄句式中，说明效果不能泛化为“所有普通建议已修复”。本轮没有临时扩大规则来迎合新例，而通过真实改稿删除“最好”和多写的参数，V4通过。录像保留V3拦截。

### 4. 固化决定

保留本次窄范围改动及反例，规则写入 `app/AGENTS.md`。不宣称语义审核全面可靠。原样本四项事实问题通过用户实际修订清除，而非关闭事实保护。

### 5. 元反思

词语命中不能区分完整建议语义。下一候选靶点是“向第三方取信息的普通建议”与真实宣传之间的判别，须另行登记反例，不能直接白名单放开“最好”。

## 实验二：并列排除项被误认成询价

### 1. 靶点与诊断证据

实际公众号重试 `final-wechat-travel-1792739864916` 包含“不写测评结论、价格或减负效果”，却结束为价格列表，无稿件。原始流及结果见 `output/demo-20261023/preflight-refinement/wechat.sse`、`results.json`。

### 2. 假设与实验设计

假设：在同一明确否定写作动词的短并列项中保留否定范围，可避免抢走创作任务，同时不吞掉后续真正询价。只改 `app/lib/price-intent.ts`，加入 `app/tests/price-exclusion-list.test.ts`。固定四条并列排除、四条真正询价，并回归旧样本。判据：4/4排除不询价，4/4询价保持；原真实重试进入写作，而不是报价。

### 3. 结果与失败样本变化

基线测试在实际“不写测评结论、价格或减负效果”失败；改后八条固定断言及47项相关测试全部通过。原任务再次原文重试，运行 `722fab37-29e4-4be4-a338-22a491bb25ac`，进入“撰写公众号稿件”，不再输出报价。流及快照：`output/demo-20261023/wechat-route-retest.sse`、`.json`。

但该次仍因正文篇幅不足而失败，没有稿件、不能导出。这证明分流问题修复，不证明长文任务成功。人工标准“继续处理写稿请求”达成；“交付长文”未达成，分别登记。

### 4. 固化决定

保留意图解析改动，长期规则写入 `app/AGENTS.md`。最终全套559项：536通过、0失败、1跳过、22待办；构建成功并运行当前版本。测试数不等于用户任务成功率。

### 5. 元反思

分流、生成、篇幅、事实保护需分层统计。下一优先候选为篇幅补救失败时的任务恢复和候选内容保留；此前两次提示扩写无整体收益，继续保持冻结，不以新一轮盲改提示掩盖问题。
