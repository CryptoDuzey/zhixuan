# 知选复赛：五天产品打磨计划

更新：2026-10-19。沿用原赛题、原仓库和已经确认的双端 Agent 方向。天数按实际工作进度安排，不把计划写成已交付能力。

## 产品目标

顾客先描述日常任务，助手帮助厘清预算、软件和系统要求，解释候选产品的取舍；营销人员接收产品与场景，产出有依据、适合平台的内容。共同目标是帮助用户做判断，让推荐有理由、文案有内容。

完整目录与可创作范围必须分开：历史实测目录为55款，10款有完整资料；只有五款具备已接入的创作素材与检查链路。MateBook 14 鸿蒙版与 Windows 版分别处理。实际数量以重新读取知识库的结果为准。

## 第一天：恢复可靠运行

- 启动授权本地知识库服务，修正在线与本地来源的区别，补上搜索和异常处理。
- 创作对话、稿件、核验结果保存到本机私密目录，刷新和服务重启后可以恢复。
- 同一任务防止重复运行；中断如实显示，不能把未完成核验当成功。
- 顾客咨询服务端保存最近12轮，支持实时步骤、停止与刷新恢复，双端交接不污染旧稿。
- 导出仅携带本会话的知识库调用，包含真实缓存使用记录。

验收：两条不同会话并发不串资料；生成途中刷新、完成后刷新、重启后恢复；旧稿修改后重新检查；缺服务、失败和损坏记录均有明确反馈。

## 第二天：让场景、推荐与内容匹配

- 复核原赛题要求与已有需求文档，建立逐项证据清单。
- 按任务、购买阶段、人群约束设计场景，先解释解决办法，再推荐候选。
- 对必用软件、系统、预算与配件有针对性地追问，减少无意义的反复澄清。
- 三个平台分别设计结构、语气与行动建议；同一产品的不同场景应有不同切入角度。
- 建立人工质量评审样例，包含不适合购买、资料不足、版本歧义和替代方案。

验收：典型咨询压缩到1—3个候选并给取舍；写作不虚构体验、不堆参数、不混型号；独立内容示例与主应用结果分别标记。

## 第三天：双端交互与视觉完善

- 保留简洁对话式界面，改善桌面画布和手机阅读、编辑、证据查看。
- 做好任务开始、进行、失败、恢复、完成和新任务的连续流程。
- 图片逐张检查，完善封面、图注、缺图与素材不足提示。
- 优化咨询到创作的交接，让产品、受众和场景可理解、可修改。

验收：真实浏览器完成选购到创作、改稿到导出；桌面与手机均无关键遮挡和无效入口。

## 第四天：有依据的热点和优惠联动

- 选择有授权且可运行的搜索或数据接口，真实接入后才宣传为已完成。
- 热点标注原始来源、发生时间与查询时间，判断与用户任务的相关性。
- 优惠保留配置、地区、资格、有效期和叠加条件；无法确认时不生成到手价。
- 先给适合用户的解决方案，再说明价格与待确认项；无关热点和促销不强行推荐。
- 对外部内容做隔离，不让网页中的指令改变系统任务或读取本地秘密。

验收：来源失效、接口失败和优惠过期时能退回普通建议；不编造热点、优惠和价格。

## 第五天：整体回归与交付

- 跑通完整场景，包括不适配产品、同名版本、多轮修改和中断恢复。
- 更新需求、开发日志、运行说明、演示脚本和 PDF 作品说明书。
- 优秀运行结果使用主应用实际输出，保存脱敏截图与时间；不把独立设计稿当运行证据。
- 完成源码检查、凭证扫描、生产构建、连续演示；核对赛方提交要求。

交付标准：可从说明书启动、关键链路真实运行、来源和边界明确、提交材料可复现。源码上传不等于公网部署或赛方平台提交。

## 当前基线与记录方式

本轮开始时前端与知识库端口均未运行。139项应用测试中136通过、3项知识库集成测试因服务未启动失败；这是开始时基线。上一轮文档与PDF已保存并上传，复赛能力以本轮新验收为准。

每次改进记录：解决的用户问题、实际改动、运行结果、尚未解决事项。规划、实现、验收通过分开标记；多窗口修改统一由统筹核查、集成和提交。
